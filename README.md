# policy-did — 정책 효과를 재기 전에 "재도 되는가"부터 묻는 도구

[English](README.en.md)

## 왜 만들었나

사업 평가나 정책연구 보고서에 "이 제도 도입으로 성과가 n% 늘었다"는 문장이 들어갑니다. 그 숫자는 대개 이중차분(DiD)이나 합성통제 같은 인과추론 방법으로 나오는데, 실무에서 문제는 계산이 아니라 그 앞에서 생깁니다. 정책을 받은 시점이 기관마다 다른데 옛날식 회귀를 돌리고, 비교할 상대가 없는데 "효과"를 쓰고, 숫자를 본 뒤에 가설을 고치고, 결과 변수가 자료에 없다는 것을 보고서를 쓰다가 알아차립니다. 추정 코드는 어디에나 있지만, "이 설계로 그 숫자를 말해도 되는가"를 먼저 묻고 안 되면 멈추는 도구는 없었습니다(2026-10 GitHub 검색: 정책평가 DiD 저장소는 전부 과제물 수준).

policy-did는 그 순서를 코드로 묶습니다. **설계서를 먼저 쓰고, 식별 가정 게이트를 통과한 설계에만 추정이 돌고, 보고서에는 "말할 수 없는 것"이 먼저 찍힙니다.** 임상시험의 사전 등록·대조군 심사와 같은 규율을 정책 자료에 적용한 것입니다.

## 어떻게 쓰나

설치가 없습니다. `policy_did.py` 한 파일을 복사하면 됩니다(표준 라이브러리만). 추정 단계에서만 R이나 Python 패키지를 부르고, 없으면 설치 명령을 알려 주고 멈춥니다.

```bash
python3 policy_did.py init --out design.yaml                 # 1. 설계서 서식 — 자료를 보기 전에 채운다
python3 policy_did.py check design.yaml --data panel.csv --out out      # 2. 게이트: PASS / WARN / FAIL
python3 policy_did.py estimate design.yaml --data panel.csv --out out   # 3. 추정 — 게이트 통과분만 돈다
python3 policy_did.py report design.yaml --data panel.csv --out out     # 4. 보고서 + 사건연구 그래프
```

`run`으로 2~4를 한 번에 돌릴 수 있고, `simulate`로 효과를 아는 합성 자료를 만들어 연습할 수 있습니다.

### 입력 1: 자료 (`panel.csv`)

단위 × 연도 긴 형식이면 됩니다. 열 이름은 설계서에서 지정합니다.

```
unit,year,exec_100m_krw
경기도,2011,19023
경기도,2012,20111
…
```

### 입력 2: 설계서 (`design.yaml`)

핵심은 다섯 가지입니다. 어느 단위가 언제 정책을 받았는가, 무엇을 재는가, 누구와 비교하는가, 효과 방향을 미리 무엇으로 보는가, 왜 비교가 성립한다고 믿는가.

```yaml
data:
  unit: unit            # 처치 단위 열(부처·시도·기관)
  time: year
  outcome: exec_100m_krw
  outcome_source: "KOSIS DT_127003_009, 조회 2026-10-20"
  log_outcome: true

treatment:
  name: "강소연구개발특구 지정"
  timing:               # 단위별 최초 처치 연도. 여기 없는 단위는 미처치
    경기도: 2019
    서울특별시: 2020
    인천광역시: 2022
  comparison: not_yet_treated   # 아직 처치되지 않은 단위와 비교

hypotheses:             # 사전 등록. direction이 없으면 설계서 오류
  - id: H1
    direction: positive
    horizon: [0, 3]     # 처치 후 0~3년까지만 말한다
    statement: "지정 후 집행액이 증가한다"

assumptions:
  sutva:
    spillover_risk: medium
    justification: "단위 간 자원 이동 가능성과 그 근거"   # 비어 있으면 FAIL
  no_other_policy: "같은 시기에 겹친 다른 정책"

design:
  method: cs            # cs(Callaway–Sant'Anna) | sa | twfe | synthdid | rdd
```

### 출력 1: 게이트 (`check`)

```
# 식별 가정 게이트 — WARN  (cs, 16 단위 · 222 행)
| ID  | 판정 | 항목                 | 내용 |
| G3  | PASS | 처치 구조            | 코호트 3개(2019, 2020, 2022), 미처치 6개 단위, staggered |
| G4  | WARN | 클러스터 수          | 16개 (기준 20) |
| G5  | PASS | 사전 추세 기울기 검정 | 코호트 합산 z=-1.28, p=0.200 |
| G2g | WARN | 시계열 단절 각주     | 2024: R&D 예산 기준 변경 — 약 1.8조원 재분류 |
→ WARN 상태로 추정은 가능하나, WARN 문장이 보고서 '말할 수 없는 것'에 그대로 들어간다.
```

FAIL이면 `estimate`가 종료 코드 3으로 멈추고 추정 파일을 만들지 않습니다. 설계서나 자료를 한 글자라도 고치면 해시가 어긋나 게이트부터 다시 돌아야 합니다.

### 출력 2: 보고서 (`report.md`)

추정표와 사건연구 그래프(처치 전후 연도별 효과, SVG) 뒤에 세 절이 붙습니다.

```
## 2. 사전 등록 가설별 판정
| H1 지정 후 집행액이 증가한다 | positive | horizon [0, 3]: 평균 0.024 | 방향 일치 (구간이 0을 포함) · 클러스터 수 부족으로 유의성 언급 보류 |

## 3. 말할 수 있는 것
- 이 추정치는 강소연구개발특구 지정을 받은 단위의 집행액이, 아직 처치되지 않은 단위와 비교해 …
- 단위가 '시도'이므로 효과는 그 수준의 평균이다. 개별 과제·기관의 효과로 옮기지 않는다.

## 4. 말할 수 없는 것 · 주의 (게이트에서 그대로 옮김)
- [G4 WARN] 클러스터 16개로 기준(20)에 못 미침 — 유의성 언어를 쓰지 않는다
- [G2g WARN] 자료 출처의 단절 각주: 2024년 R&D 예산 기준 변경 …
```

## 용어 한 줄씩

- **이중차분(DiD)**: 정책을 받은 집단의 전후 변화에서 안 받은 집단의 전후 변화를 빼서 효과를 재는 방법. 두 집단이 정책 없이는 같은 추세였다는 가정(평행추세)이 핵심.
- **staggered**: 단위마다 정책을 받은 시점이 다른 경우. 이때 전통적 이원고정효과 회귀(TWFE)는 이미 처치된 단위를 비교군으로 쓰는 편향이 생겨, 이 도구는 그 조합을 FAIL로 막는다.
- **ATT**: 처치받은 단위에서의 평균 효과. 보고서의 "전체 ATT"와 연도별(사건연구) ATT.
- **게이트**: 추정 전에 돌리는 식별 가정 점검표. PASS·WARN·FAIL.
- **합성통제(synthdid)**: 비교군을 여러 미처치 단위의 가중 평균으로 만드는 방법. 도입 시점이 하나일 때만.
- **회귀불연속(RDD)**: 점수 기준으로 선정되는 정책에서 기준점 바로 위·아래를 비교하는 방법.

## 무엇을 점검하나

| ID | 점검 | FAIL | WARN |
|---|---|---|---|
| G1 | 가설 방향 사전 등록, 등록일 | 방향 없음 | 등록일 없음 |
| G2 | 결과변수가 자료에 있는가, 결측, 시점표↔자료 단위 일치, 출처의 시계열 단절 각주 | 결측 >50%, 시점표에만 있는 단위 | 결측 >10%, 단절 각주 |
| G3 | 비교군 유무, staggered 여부, 방법 적합 | 비교군 없음, staggered + TWFE | 미처치 없는 마지막 코호트 |
| G4 | 클러스터 수, 코호트당 단위 수, 사전·사후 기간 | 클러스터 <5, 사전 기간 <2 | 클러스터 <20, 단위 1개 코호트 |
| G5 | 사전 추세(코호트별 같은 창에서 단위별 기울기 비교) | — | p<0.10 |
| G6 | 파급(SUTVA) 근거, 동시 정책 | 근거 없음 | 위험 medium/high |
| G8 | 추정기 설치 여부 | 없음 | — |
| G9 | (RDD) 절단점 범위, 양쪽 관측 수, 밀도 | 절단점 범위 밖 | 한쪽 <30, 밀도 비대칭 |

사전 추세 검정은 통과해도 평행추세의 증명이 아닙니다(Roth 2022). 보고서는 PASS여도 그 문장을 남깁니다.

## 추정기 (직접 만들지 않고 부릅니다)

| method | 호출 | 조건 |
|---|---|---|
| `cs` | R `did::att_gt`, 없으면 Python `differences` | staggered 가능 |
| `sa` | R `fixest::sunab` | staggered 가능 |
| `twfe` | Python `statsmodels` | 단일 도입 시점만 |
| `synthdid` | R `synthdid` | 단일 도입 시점·미처치 donor |
| `rdd` | R `rdrobust` | 배정 변수·절단점 |

`python3 policy_did.py engines`가 설치 상태와 설치 명령을 보여 줍니다.

## 예시

- `examples/synthetic/` — 효과를 아는 합성 자료. R `did`와 Python `differences`가 같은 값을 내고 참값(2.0 + 0.5/년)을 회복합니다.
- `examples/innotown_region/` — 강소연구개발특구 지정(2019·2020·2022, 특구재단 원문 `sources.md`) × 시도별 정부 R&D 집행(KOSIS). 게이트 WARN으로 통과, 효과는 방향만 맞고 구간이 0을 포함. 설계서에 "검출되지 않을 가능성이 크다"고 미리 적었고 결과가 그렇습니다.
- `examples/kosis_budget_cut_2024/` — 2024년 R&D 예산 삭감 × 부처별 집행. 모든 부처가 같은 해에 처치돼 비교군이 없고 같은 해 기준 변경이 겹쳐 **게이트 FAIL**. 집계 자료로 "삭감 효과"를 말할 수 없다는 것을 도구가 먼저 말한 예시.

[kr-sti-data](https://github.com/parkjui92/kr-sti-data)의 KOSIS export는 `panel` 명령으로 바로 패널로 바꿀 수 있고, 머리의 `# 시계열 단절` 각주가 게이트 WARN으로 이어집니다.

## 하지 않는 것 · 한계

- 연속 처치(처치 강도 차이)·삼중차분·HonestDiD 민감도 분석은 범위 밖
- 공변량은 설계서에 자리만 있고 추정에 아직 넘기지 않는다
- 사전 추세 검정은 단위별 선형 기울기 비교의 간이판. 정식 검정은 R `pretrends`·`HonestDiD`
- RDD 밀도 점검은 `rddensity`의 대용
- 내장 YAML 파서는 설계서 서식의 부분집합만 읽는다(PyYAML이 있으면 그것을 쓴다)

## 정직성 규칙 (출력에 그대로 찍힙니다)

1. 가정 미충족(FAIL)이면 추정치가 없다.
2. 등록한 가설·결과변수·horizon에 대해서만 말한다.
3. 게이트 WARN은 지우지 않고 보고서에 ID와 함께 옮긴다.
4. 사전 추세 검정 통과 ≠ 평행추세. PASS여도 그 문장을 남긴다.
5. 클러스터가 적으면 유의성 언어를 쓰지 않는다.
6. 단위 수준을 넘어 해석하지 않는다.
7. 설계서·자료의 해시가 모든 산출물에 들어가고, 바뀌면 처음부터 다시 돈다.
8. 추정기를 지어내지 않는다. 없으면 설치 안내만 내고 멈춘다.

## 검증 상태 (2026-10-20)

- 합성 staggered 패널(60단위·15년·코호트 3): `r:did`·`py:differences` 동일값, e=0 2.05(참값 2.0) … e=4 4.07(참값 4.0), 사전 기간 −0.12~−0.01
- `sa` 4.30 vs `cs` 4.29(같은 자료). 단일 코호트: `twfe` 3.52·`synthdid` 3.54(참값 평균 3.5). RDD: `rdrobust` 3.25(SE 1.06, 참값 5, 강건 CI가 참값 포함)
- 게이트 거부 경로 5종(staggered+TWFE, 비교군 없음, SUTVA 근거 없음, 시점표에만 있는 단위, 설계 변경 후 추정) 차단 확인
- 실제 자료 1건 완주(`examples/innotown_region/`), tests 18건(`python3 policy_did.py selftest`)

설계 결정과 근거는 [docs/design.md](docs/design.md).
